# Lecture Enhancer

Turn a dropped YouTube link (or channel) into measured, verified improvements
to the `book/` lectures in this learning repo.

## The workflow

1. **Download the transcript(s)** → deposit in `book/assets/transcripts/`.
2. **Audit each transcript against the lectures** that could plausibly host it.
3. **Verify every number** against the primary paper or your own arithmetic.
4. **Improve the lectures** (or, if unsure, report options before editing).
5. **Rebuild** with `uv run mkdocs build --strict` (must stay warning-free).

## Step 1 — Downloading transcripts

For a channel: enumerate videos first, **skip Shorts**, download the rest.

```bash
# enumerate regular videos (skips nothing, but DON'T add shorts to the script)
uvx yt-dlp --flat-playlist --print "%(id)s|%(title)s" "https://www.youtube.com/@CHANNEL/videos"
```

Download with `youtube-transcript-api` (the same engine the MCP server
`kimtaeyoon83/mcp-server-youtube-transcript` wraps — no need for the MCP
server itself, it needs a session restart to load):

```python
from youtube_transcript_api import YouTubeTranscriptApi
api = YouTubeTranscriptApi()
got = [t for t in api.list(video_id) if t.language_code.startswith("en")]
for t in got:
    if not t.is_generated:
        break          # prefer manually-created captions
parts = t.fetch()
```

Naming: `<video_id>_<kebab-slug>.txt` in `book/assets/transcripts/`. Header:

```
# <kebab-slug>
# video: https://www.youtube.com/watch?v=<id>
```

**Fallback when the API is IP-blocked** (`RequestBlocked`/`IPBlocked`, common
after bulk downloads): retry a few times with ~20s backoff; if still blocked,
load the **kimi-webbridge skill** and drive the user's real browser: open the
video page, open the transcript panel, and pull the segments. Mark autogenerated
captions: clean the text but keep them (they're still useful).

**Guidelines:** if the user says "don't do shorts", never include `shorts` tab
videos. Only regular videos.

## Step 2 — The audit (multi-pass)

Run passes as parallel subagents (`general`), grouped by topic family:

- attention → lectures 01, 02, 05, 16, 17, 18
- MoE/parallelism/costing → 21, 22, 23, 27, 28
- serving/production → 09, 24, 25, 26, 29

Each pass requires, per transcript:

1. **Verified numbers/facts NOT in the lectures** — compute or confirm the
   arithmetic yourself; give exact figures and where they fit.
2. **Claims that CONTRADICT or nuance the book** — side by side; state which
   is right, with the math.
3. **Exposition worth stealing** — analogies, worked examples, ordering tricks,
   with the transcript's phrasing.
4. **Candidate qa.md questions** — genuine confusion a reader would hit.
5. **Anything questionable in the video** — wrong numbers, overclaims,
   skipped derivations, ASR garbles.

Tell subagents to cite `file:line` on both sides and rank high/medium/low.
The book's rule for numbers: derive everything, condense nothing. A video
that repeats a known number adds nothing: only *new, verified* arithmetic
gets in. Cross-check against the primary paper (arXiv) — short "bite" videos
contain more errors than the long ones (e.g. 600B for 671B, "7B base scores
51%" when that's the RL model).

## Step 3 — Improving the lectures

Respect repo conventions (CLAUDE.md):

- **qa.md + collapsible pairing**: every `??? question` collapsible gets a
  `##` entry in `book/qa.md` (answer the *actual* question, include the wrong
  intuition), and the lecture gets the collapsible at the exact stall point.
  Rephrase lecture math if an answer contradicts it — and say so.
- **Go deeper**: add video references with channel name + link where they
  genuinely deepen (the Papers by Hand vLLM video already anchors 09/10/18).
- **Measure first** ethos: don't add paper numbers as the headline; frame
  them as what others measured, with your own bench number as the lesson.
- Math style: full derivation of every step, then numbers plugged in.

## Step 4 — Verify + commit

```bash
uv run mkdocs build --strict
uv run pytest tests/ -q            # if code touched
```

Commit pattern: `book: <lecture>: <what changed from <source video>`. Commit
transcript drops and lecture edits together. Push when asked. Leave failures
and wrong predictions unedited.

## Known source quirks

- **Papers by Hand** (inference heavy): GQA/FlashAttention/MoE/V3/V4/vLLM
  videos verify clean against papers; keep the vLLM video (`xgl9Qrz31Mc`)
  as THE reference for 09/10/18. Short "bite" videos are compressed versions
  of the deep dives (ASR garbles: "slice each one in two" = "into four").
- **Dwarkesh Patel / Reiner Pope** (training + serving + chip design):
  long-form; transcripts come back autogenerated; numbers should be checked
  against the actual paper cited in-conversation, they claim more than they
  prove.
- **Claude Code harness videos**: nearly out of scope (agent harnesses, not
  serving) — steal the *exposition* framing if anything ("lazy degradation",
  "failure becomes a signal"), not the numbers.
